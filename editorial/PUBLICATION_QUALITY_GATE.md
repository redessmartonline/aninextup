# AniNextUp — Mandatory publication quality gate

## New-article standard — owner instruction, October 28, 2026

This standard applies to articles created after this instruction. It supersedes earlier 800–1,000-word targets for NEW articles; it does not require bulk expansion of existing articles.

- Write **1,200–2,000 words of original English main editorial content**. Count the lead and substantive article text, excluding navigation, metadata, source lists, captions, repeated table labels, related cards and footer.
- Before drafting, identify one primary user search intent, one primary keyword cluster and relevant secondary questions. Use current Search Console signals when available; do not invent search volumes, difficulty scores or ranking forecasts.
- Search existing canonical articles, aliases and open editorial work first. Update an existing page when it serves the same intent rather than create competing duplicate pages.
- Answer the main question directly in the opening. Organize useful H2/H3 sections around actual reader questions, not a repeated template or a fixed keyword density.
- Cover relevant release dates, exact versus year/month-only windows, platforms, countries, language versions, episode information, watch order and story context ONLY when those questions fit the topic and the evidence supports the answers. State unknowns clearly.
- Add original editorial value through source comparison, clear release-scope distinctions, useful tables or explanations; distinguish interpretation from confirmed facts. Never add filler, repeated paragraphs, invented FAQs or unsupported claims to reach the range. If the evidence cannot support 1,200 useful words, choose a better-supported topic or update an existing guide; flag the shortfall instead of publishing it as compliant.
- Use a concise, descriptive SEO title and unique description, one H1, clear headings, a preserved canonical URL and accurate structured data. Place keywords naturally; avoid stuffing, clickbait and unsupported promises.
- Add relevant contextual internal links and exactly three related cards with real destination artwork. Keep the verified official cover and embed an official trailer whenever one is available.
- Record the word count, primary intent, target keyword cluster, questions answered, sources and verification limits in the editorial review record.
- Validate factual accuracy, useful answers, images, video, links, metadata, index/sitemap inclusion and deployed rendering. Assess Search Console impressions, clicks, CTR and position after recrawling; length and SEO edits do not guarantee Google rankings.

Applies to **every** new or updated article, whether manually authored or generated by Auto Publisher. Reference the full structure of `articles/nues-exorcist-anime-summer-2027.html` and the corrected `articles/the-fable-season-2-january-2027.html`. Never substitute a minimal HTML article. The three-card standard reflects merged site-wide migrations in PRs #220 and #224.

## Mandatory two-stage publication approval

**STAGE 1 — PREPARE AND REVIEW (ONE COMBINED STAGE):** Research, write, check, fix and revalidate the complete article within the same stage until all mandatory checks pass. It may be saved only as an unpublished draft or editorial pull request. Present the fully prepared and reviewed draft, with quality-check results, to the owner. Preparing, reviewing, or approving the *topic* is **not** permission to publish.

**STAGE 2 — PUBLISH:** Publish or merge into the production `main` branch **only after the owner explicitly says "PUBLÍCALO" (or an equally unambiguous instruction to publish that specific article)**. No automatic merging, no scheduled article publication, and no treating passing tests as publishing approval. If approval is absent, keep the draft pending. After explicit approval, publish and verify the live URL.

## Mandatory FIRST action: search for duplicates BEFORE writing

Before creating any article draft, search the entire existing `articles/` directory, `assets/data.js`, `sitemap.xml`, and open editorial PRs using the anime's canonical title, aliases, romanizations, franchise name, and topic keywords. If a page already covers the same series or announcement, UPDATE that existing canonical page and preserve its URL; never create a second article. Distinguish new facts worthy of updating from truly independent subjects. If uncertain, flag for manual editorial review and do not create a new page. The automated workflow also runs `python scripts/check_article_duplicates.py` before synchronizing article metadata or opening an approval PR. A passing automatic check does not replace the manual pre-draft search.

## Block publication until all required checks pass

- [ ] Original English article; accurate official source links, broadcast dates/time zones, cast/staff, streaming, and clearly distinguished unknowns. Never infer a specific day from a month-only announcement.
- [ ] Consistent site header/menu/nav, kicker, H1, lead, byline/editorial-policy link, main article prose, updated timestamp, report-error link, footer, CSS and JS.
- [ ] Verified, topic-specific **official hero visual** with working URL, descriptive alt, caption, source/credit. If unavailable, mark **BLOCKED: IMAGE UNVERIFIED**, not a substitute or generic image.
- [ ] SEO title/description, canonical, robots, OpenGraph title/description/url/image, Twitter large-image card, favicon, NewsArticle and BreadcrumbList JSON-LD, `aninextup-index` JSON with correct image.
- [ ] `Release at a glance` with accurate dates, studio, broadcaster/streaming and source; substantive sections covering the confirmed news.
- [ ] When a verified official YouTube teaser exists: `lite-trailer` with real video ID, accessible play button, thumbnail, fallback YouTube link and VideoObject, including an ISO 8601 `uploadDate` including the verified time and timezone offset from the original video (date-only values are blocked) (never copy the article date). Never invent a video ID or claim a trailer is absent without checking.
- [ ] `KEEP WATCHING` and `Related releases` headings **exactly**, in `section.related-releases[aria-labelledby="related-releases-heading"]` with `div.section-head`, `div.grid.three` and three **existing** related articles. Each anchor must have `mini related-card`, `img.related-card-image` (verified relevant thumbnail; width=160 height=90, loading=lazy, decoding=async, graceful onerror), and `div.related-card-copy` containing H3 and "Read the guide →". No plain-text-only cards.
- [ ] Article route exists, related routes resolve, sitemap.xml and assets/data.js entries are correct, no duplicate stories, date labels match verified evidence.
- [ ] HTML/JSON-LD syntax and link/image accessibility checked; compare the rendered desktop page with the full reference article. Check the rendered mobile layout when device-width emulation is available. If the browser tooling does not expose mobile emulation, record `MOBILE VISUAL: NOT TESTED — device emulation unavailable`; this item alone does not block publication when all remaining checks pass. Never label the mobile check passed without a real mobile-width rendering.
- [ ] Write with current GitHub blob SHA; confirm commit, fetch saved file and assert mandatory sections.
- [ ] Verify deployed public URL and actual visual rendering. If deployment or public verification fails, report **NOT VERIFIED**, never "fully published".

**Failure handling:** If any required check fails, leave the article in preparation/review rather than claiming successful publication. Log the specific missing element, fix it, and rerun the checks. An official trailer is conditional on existence; never fabricate one. Explicit user approval is required before publishing articles.

## Non-negotiable artwork protection (homepage and articles)

A generic site placeholder is **not** a publishable anime image. Before an article enters `main`, check all of the following and record the results in the editorial PR:

1. `assets/data.js` news entry `image` must point to a genuine image for the named anime. Reject `anime-image-fallback.svg`, empty URLs, unrelated stock images and unrelated YouTube thumbnails.
2. The article hero `img[src]`, `og:image`, `aninextup-index.image` and `NewsArticle.image` must resolve to the correct artwork; avoid mixing a verified article image with a generic homepage image.
3. Test HTTP status, image MIME type, nonzero dimensions, and visual subject identity. A URL string or a 200 response alone does not establish that an image depicts the right anime.
4. Inspect the homepage news card, article hero and all three related-release cards in a real desktop browser layout. When device-width emulation is available, inspect them in mobile layout too. If mobile emulation is unavailable, record `MOBILE VISUAL: NOT TESTED — device emulation unavailable` and continue only after all other image, link, responsive-source and automated checks pass. Never claim an unperformed mobile visual check passed.
5. On any failed or unverified check, leave the article **BLOCKED: IMAGE UNVERIFIED** and unpublished. Fix and rerun the checks; never silently substitute site branding and call the result complete.
6. When a publisher explicitly authorizes publication, report any missing public-browser verification truthfully. Mobile visual inspection is conditional on the browser tooling exposing device-width emulation; no other image verification may be skipped.

The generic fallback may remain an emergency runtime safeguard for unexpected network errors, but it must **never** be configured as the primary editorial artwork.
